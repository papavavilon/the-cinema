# The Cinema

PHP/MySQL-проєкт кінотеатру. Код організовано за підходом MVC із наданого референса.
Головна адреса у XAMPP — http://localhost/dwp/.
Робоча база — `thecinema_v2`.

## Запуск після клонування з GitHub

1. Розмісти проєкт у папці `dwp` всередині `htdocs` XAMPP.
2. Скопіюй `config/database.example.php` у `config/database.php` та заповни доступ до бази.
3. Скопіюй `config/mail.example.php` у `config/mail.php`. SMTP можна налаштувати пізніше.
4. Для нового встановлення імпортуй структуру з `database/schema.sql` або повний приватний резервний експорт.
5. Запусти Apache і MySQL та відкрий http://localhost/dwp/.

На вже налаштованому комп’ютері використовуй наявну базу `thecinema_v2`.
Локальні конфігурації та експорт із даними виключені з Git. Структура бази доступна в репозиторії.

## Як проходить запит

1. `index.php` отримує адресу сторінки та обирає контролер.
2. Контролер перевіряє форму, права доступу й потрібні дані.
3. Модель виконує SQL-запити через PDO з окремими параметрами.
4. Шаблон показує готові дані у HTML.
5. CSS оформлює сторінку. JavaScript керує меню, підсумком місць, підтвердженням і друком.

Основні правила бронювання, ціни, знижки, доступ та збереження замовлення перевіряє PHP.

| Папка | Призначення |

| `frontend/controllers` | Сторінки та обробка форм відвідувачів |
| `frontend/models` | Запити до бази для відвідувачів |
| `frontend/views` | HTML сторінок і спільних елементів |
| `frontend/assets/css` | Стилі за частинами сайту |
| `frontend/assets/js` | Меню, вибір місць і прості дії форм |
| `admin/controllers` | Дії працівника кінотеатру |
| `admin/models` | Запити адмінпанелі до бази |
| `admin/views` | Окремі шаблони таблиць, форм, повідомлень і бронювань |

## Приклади OOP

`Database` створює підключення до бази.
`MoviesController` отримує фільтри каталогу та створює `MoviesModel`.
`MoviesModel` знаходить фільми за переданими фільтрами.
`CheckoutAction` перевіряє замовлення та використовує `CheckoutModel` для запису.
`MailService` налаштовує PHPMailer і надсилає лист.

Контролери реально створюються маршрутизатором. Моделі створюються відповідними контролерами.
`BaseModel` дає моделям спільний спосіб виконувати підготовлені SQL-запити.
MVC розділяє отримання даних, обробку запиту та відображення сторінки.

## База даних

`database/schema.sql` створює 24 таблиці, 2 views та 2 triggers у новій порожній базі.
Це структура без даних. Для відновлення наявних фільмів і бронювань потрібен повний резервний SQL-експорт.
У вже налаштованому XAMPP повторний імпорт для цієї перебудови не потрібен.

Тригери перевіряють накладання сеансів під час додавання та редагування.
Між показами враховано 15 хвилин перерви.
Унікальне обмеження `unique_screening_seat` забороняє два квитки на одне місце одного сеансу.
Під час бронювання PHP блокує запис сеансу й зберігає весь набір записів однією транзакцією.

## Пошта

У `config/mail.php` підготовано SMTP-підключення. За погодженням із власником надсилання зараз вимкнене.
Потрібно заповнити сервер, порт, шифрування, логін, пароль, адресу відправника та адресу власника.
Після цього `enabled` можна встановити в `true`.
`base_url` задає адресу посилань для відновлення пароля.
PHPMailer використовує ті самі PHP-технології, що й референс.
PHP-файли PHPMailer підключаються безпосередньо через `require_once` у `MailService.php`.
Локальні копії листів доступні працівнику в адмінпанелі.

## Що ще потребує окремого етапу

SMTP-налаштування, публікація на live server, DB-діаграма, sitemap, flowchart та екзаменаційний звіт.
Оплата залишається демонстраційною. У завданні справжня оплата зазначена як бажана.
Перелік перевірених вимог є в `docs/requirements.md`.
